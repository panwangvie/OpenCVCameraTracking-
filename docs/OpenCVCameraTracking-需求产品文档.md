# OpenCVCameraTracking 需求产品文档

版本：v1.0

本文是 OpenCVCameraTracking 后续产品和技术迭代的统一需求文档，汇总了摄像头接入、AI 检测识别、目标跟踪、录像告警、数据安全和用户体验等内容。

## 1. 产品定位

OpenCVCameraTracking 是一款基于 .NET 8、WPF 和 OpenCvSharp 的 Windows 本地摄像头分析工具，面向家庭、办公室、小型门店和个人开发者，提供：

- USB/内置摄像头、RTSP/HTTP 网络视频流和本地视频文件预览。
- 人脸、动物和复合目标检测。
- 多目标跟踪、白名单识别和陌生目标提示。
- 本地优先的数据处理方式。
- 可选的事件录像、桌面通知和外部告警联动。

产品目标是从“可以看到并识别”逐步升级为“稳定接入、准确识别、事件可追溯、告警可联动”。

## 2. 当前版本能力基线

当前项目已经具备以下基础能力：

- Windows 视频设备枚举和打开。
- RTSP、HTTP 网络视频流和本地视频播放。
- RTSP/TCP、读取超时、断线重连和最新帧低延迟处理。
- YuNet ONNX 人脸检测和五点关键点定位。
- SFace ONNX 人脸对齐、特征提取和白名单匹配。
- YOLOX INT8 ONNX 动物检测。
- 自定义 YOLOv5/YOLOv8 ONNX 模型导入。
- 人脸、动物和“人 + 动物”复合检测模式。
- IoU 多目标关联、TrackId、位置平滑和短时丢失保留。
- 人脸/猫白名单录入、圈选录入、缩略图和大图查看。
- 陌生人提示、识别记录、本地日志和 Microsoft Store 更新提醒。

## 3. 用户和典型场景

### 3.1 家庭用户

- 查看客厅、门口或宠物活动区域。
- 识别家庭成员和陌生人。
- 识别猫、狗等宠物。
- 陌生人出现时通知并保存片段。

### 3.2 办公室或小型门店

- 同时查看多路摄像头。
- 在指定区域识别人和动物。
- 对陌生人、越线和长时间停留触发告警。
- 按日期检索事件并导出证据。

### 3.3 开发和测试人员

- 导入本地视频或自定义 ONNX 模型。
- 调整检测和匹配阈值。
- 查看原始置信度、推理耗时和日志。
- 验证不同摄像头、编解码器和模型的效果。

## 4. 公开反馈归纳的主要痛点

### 4.1 RTSP 连接稳定性

公开 OpenCV issue 中有 RTSP 在 VLC/FFmpeg 可以播放、但 `VideoCapture` 出现读取超时或无法抓帧的案例；另有反馈指出异常断开时 `read()` 可能长时间阻塞。

- [OpenCV RTSP 抓帧超时 issue](https://github.com/opencv/opencv/issues/27091)
- [OpenCV-Python VideoCapture 超时 issue](https://github.com/opencv/opencv-python/issues/788)

产品需要给用户明确的连接状态、延迟和重连结果，而不是只显示“黑屏”。

### 4.2 识别结果跳变

逐帧独立判断会受到光照、压缩、侧脸、遮挡、模糊和丢帧影响，导致同一个目标在白名单和陌生人之间快速切换，并产生重复记录。

### 4.3 识别结果缺少解释

用户需要区分：人脸检测置信度、身份匹配相似度、图像质量和最终状态，不能只看到一个百分比。

### 4.4 缺少事件闭环

仅显示检测框和记录不足以满足监控场景。用户通常还需要录像、快照、时间线、通知和导出。

### 4.5 单路预览限制

同类项目普遍提供多摄像头网格、全屏、自动重连和布局保存。

- [OpenIPC Viewer](https://github.com/OpenIPC/viewer)
- [OpenDVR](https://github.com/ceelsoin/opendvr)

### 5.2 人脸检测和识别

#### P0

- 分离显示检测置信度和身份匹配度。
- 人脸检测阈值、白名单匹配阈值和陌生人告警阈值独立配置。
- 轨迹级身份状态机和多帧投票。
- 进入阈值和退出阈值使用滞回，降低临界值抖动。
- 同一 TrackId 在冷却时间内只产生一次事件。
- 白名单成员支持 3～5 个不同姿态样本。
- 录入前进行人脸尺寸、清晰度、亮度和关键点检查。

#### P1

- 显示姿态质量：正面、轻微侧脸、侧脸角度过大。
- 识别失败时显示原因：人脸过小、模糊、过暗、遮挡或关键点缺失。
- 一个成员保存多个特征向量，支持最高相似度、Top-K 平均值和加权平均值。
- 白名单样本导入、导出和批量管理。
- AI 调试模式显示原始相似度、映射百分比、状态切换原因和模型耗时。

#### P2

- 活体检测。
- 屏幕、照片和视频攻击识别。
- 眨眼、转头等动作挑战。
- 跨摄像头身份关联。

YuNet 官方说明其输出包含人脸框和五个人脸关键点；SFace 官方示例采用对齐裁剪、特征提取和余弦相似度匹配流程。

- [YuNet 官方说明](https://github.com/opencv/opencv_zoo/blob/main/models/face_detection_yunet/README.md)
- [SFace 官方示例](https://github.com/opencv/opencv_zoo/blob/main/models/face_recognition_sface/demo.cpp)

推荐界面显示：

```text
检测置信度：92%
身份匹配度：86%
图像质量：良好
判断结果：白名单
```

推荐判断逻辑：

```text
检测置信度 >= 人脸检测阈值
并且

```

- 内置默认动物模型。
- 显示类别、检测置信度和 TrackId。
- 支持按类别启用或禁用。
- 每个类别独立设置置信度阈值。

- 猫、狗、人、鸟等常用类别筛选。

#### P2

- 动物特征提取模型。
- 多角度宠物样本管理。
- 已知宠物、未知宠物和其他动物分类。

### 5.4 目标跟踪和状态稳定

建议以 TrackId 为单位维护状态：

```text
未确认
  ↓ 连续多帧达到匹配阈值
候选身份
  ↓ 投票达到确认条件
已确认白名单
  ↓ 连续多帧低于失配阈值
陌生人 / 未知
```

默认建议：

```text
连续 5 帧中至少 3 帧匹配：确认身份
连续 5 帧中至少 4 帧失配：切换为陌生人
身份确认后：允许少量异常帧，不立即切换
同一 TrackId：在冷却时间内只记录一次事件
```

建议支持：

- 动态调整检测帧率。

### 5.10 大模型接入：DeepSeek 等 AI 服务

#### 5.10.1 产品定位

DeepSeek 等大语言模型适合处理“检测结果之后”的事件理解、自然语言交互和报告生成，不适合替代 YuNet、YOLO 等逐帧实时检测模型。

推荐采用以下分层：

```text
摄像头帧
   ↓
YuNet / YOLO / SFace / 跟踪器
   ↓
结构化事件（时间、摄像头、目标、TrackId、置信度、快照）
   ↓ 仅在满足规则时异步调用大模型
DeepSeek 等 AI 服务
   ↓
事件摘要、告警文案、自然语言查询或规则 JSON
```

这样可以保持实时检测的低延迟，同时避免把每一帧视频都上传到云端。

#### 5.10.2 首选功能需求

##### P1：事件摘要和告警文案

- 将结构化识别事件转换为人类可读描述。
- 生成中文或 English 告警内容。
- 对同一时间段的多个事件进行合并摘要。
- 在通知中包含摄像头名称、时间、目标类型、身份状态和置信度。
- 由本地规则决定是否发送，模型只负责描述，不负责直接触发告警。

示例输入：

```json
{
  "camera": "FrontDoor",
  "time": "2026-09-12T21:30:00+08:00",
  "target": "person",
  "identity": "unknown",
  "detectionConfidence": 0.91,
  "matchScore": 0.18,
  "dwellSeconds": 12
}
```

示例输出：

```text
21:30，前门摄像头检测到一名陌生人，停留约 12 秒，建议查看事件快照。
```

##### P1：自然语言查询事件记录

用户可以输入：

```text
昨晚 22 点以后有没有陌生人出现在门口？
上周出现次数最多的动物是什么？
把今天所有未识别的人脸列出来。
```

模型只将问题转换为受限查询条件，实际筛选由本地事件数据库执行，避免模型直接编造结果。

##### P1：自然语言创建检测规则

用户可以输入：

```text
每天晚上 10 点到早上 6 点，门口检测到陌生人时保存 20 秒录像并发出声音提醒。
```

模型输出经过 JSON Schema 校验的规则对象，再由本地界面展示预览，用户确认后才保存。

##### P1：日志和故障分析助手

- 汇总 RTSP 断线、模型加载失败和推理超时日志。
- 用自然语言解释可能原因。
- 给出重连、码流切换、模型路径和性能调优建议。
- 默认只发送经过脱敏的错误摘要，不发送密码、完整 RTSP 地址或白名单样本。

##### P2：事件日报和周报

- 统计每天各摄像头的在线时间、事件数量和目标类别。
- 统计陌生人、白名单成员和动物事件。
- 生成自然语言日报或周报。
- 支持导出 Markdown、HTML 或 PDF。

##### P2：图片理解（可选）

如果用户明确开启，可将单张事件快照交给支持视觉输入的大模型生成补充描述，例如“目标是否携带包裹”。该能力只作为辅助描述，不能覆盖本地检测器的身份判定和告警结论。

#### 5.10.3 DeepSeek API 接入要求

DeepSeek 官方 API 提供 Chat Completions 接口，并支持 JSON Output、工具调用和流式响应；官方文档也列出了视觉输入模型能力。接口和模型名称可能随服务更新，因此应通过配置选择，不要把模型名称写死在业务逻辑中。

- [DeepSeek Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)
- [DeepSeek Responses API](https://api-docs.deepseek.com/api/create-response/)
- [DeepSeek API JSON Output 与 Function Calling](https://api-docs.deepseek.com/news/news0725/)

建议抽象统一接口：

```csharp
public interface ILanguageModelClient
{
    Task<string> SummarizeEventAsync(
        RecognitionEventSummary summary,
        CancellationToken cancellationToken);

    Task<RuleDraft> ParseRuleAsync(
        string naturalLanguageRule,
        CancellationToken cancellationToken);
}
```

配置项建议包括：

```text
Provider：DeepSeek / OpenAI-compatible / 本地模型
BaseUrl：由用户配置
Model：由用户选择
EnableCloudAi：是否允许联网调用
SendEventSnapshots：是否允许上传事件快照
RequestTimeoutSeconds：请求超时
DailyRequestLimit：每日请求上限
```

API Key 必须使用 Windows Credential Manager、DPAPI 或系统安全存储，不能写入 Git、普通 JSON 配置、日志或 MSIX 包。

#### 5.10.4 事件调用策略

不应为每一帧调用大模型，建议只在以下情况调用：

- 本地规则确认发生陌生人事件。
- 同一 TrackId 结束后需要生成摘要。
- 用户主动查询历史事件。
- 用户主动请求分析日志。
- 用户明确点击“分析此快照”。

建议增加：

- 请求队列和并发上限。
- 8～15 秒请求超时。
- 失败重试和指数退避。
- 相同事件去重。
- 每日调用次数限制。
- 断网时自动降级为本地模板文案。
- 上下文和重复事件摘要缓存。

DeepSeek 官方提供上下文缓存能力，可用于重复的系统提示和事件格式，但缓存命中并非绝对保证；项目仍应自行控制发送内容、保留时间和隐私开关。

- [DeepSeek Context Caching](https://api-docs.deepseek.com/guides/kv_cache/)

#### 5.10.5 隐私策略

默认关闭云端 AI，首次启用时明确提示：

```text
启用云端 AI 后，选定的事件文本或快照可能会发送到第三方模型服务。
请确认已获得相关人员授权，并避免上传包含密码、完整地址或敏感个人信息的内容。
```

建议提供三个级别：

```text
仅本地：不调用云端，只使用 OpenCV/ONNX 模型
事件文本：只发送脱敏后的结构化事件，不发送图片
事件文本 + 快照：在用户确认后发送单张事件图片
```

脱敏规则：

- 删除 RTSP 用户名、密码和完整地址。
- 使用摄像头别名替代 IP 地址。
- 使用“白名单成员 A”替代真实姓名。
- 默认裁剪或模糊其他人脸。
- 不发送连续视频流。
- 日志不记录 API Key 和完整请求内容。

#### 5.10.6 Function Calling 安全边界

大模型不得直接执行删除白名单、删除录像、修改摄像头地址或发送外部通知等高风险操作。

工具调用必须经过：

```text
模型提出工具调用
    ↓
本地 JSON Schema 和参数校验
    ↓
权限和风险检查
    ↓
用户确认（高风险操作必需）
    ↓
本地服务执行
    ↓
记录审计日志
```

初期只允许只读工具：

- 查询事件。
- 查询摄像头状态。
- 查询模型状态。
- 汇总日志。

DeepSeek 官方文档也提示，模型生成的工具参数仍需在客户端验证，不能直接信任模型返回值。

#### 5.10.7 本地模型兼容

为了降低隐私、网络和费用风险，建议把大模型客户端设计为可插拔：

- DeepSeek API。
- OpenAI-compatible API。
- Ollama 或兼容本地推理服务。
- Windows 本地 ONNX/小型语言模型。

AI 服务不可用时，核心检测、识别、录像和告警必须继续工作。

## 6. AI 评测体系

建立固定测试集，覆盖：

- 正面、左侧、右侧、抬头和低头。
- 不同光照、距离和分辨率。
- 戴眼镜、口罩和帽子。
- 单人、多人和部分遮挡。
- RTSP 丢帧和短暂断线。
- 白名单成员和陌生人混合出现。
- 猫、狗和复杂背景。

每次模型或阈值修改后记录：

```text
检测召回率 Recall
误检率 False Positive Rate
白名单误识率 False Accept Rate
陌生人漏报率 False Reject Rate
平均推理耗时
端到端视频延迟
```

验收时不能只使用一张截图判断效果，应保留测试集、阈值和结果。

## 7. 非功能需求

### 7.1 稳定性

- 摄像头异常、模型异常和 UI 异常互相隔离。
- 长时间运行不持续增长内存和帧队列。
- RTSP 断线后自动恢复。
- 所有后台任务在窗口关闭时可取消并释放资源。

### 7.2 性能

- UI 线程不执行模型推理和磁盘 I/O。
- 低延迟模式优先处理最新帧。
- 录像写入和识别日志写入使用后台线程。
- 显示采集、推理和 UI 三类 FPS。

### 7.3 可维护性

- 检测器、识别器、跟踪器、录像器和通知器使用独立接口。
- 模型配置、摄像头配置和事件规则分离。
- 关键操作写入结构化日志。
- 为 RTSP、模型加载、识别状态机和录像建立自动化测试。

### 7.4 本地化和可用性

- 中文和 English 运行时切换。
- 错误信息包含可执行的处理建议。
- 提供简洁模式和 AI 诊断模式。
- 小尺寸窗口下工具栏不出现明显的长滚动条。
- 关键按钮支持键盘操作和无障碍访问。

## 8. 版本路线图

### 第一阶段：稳定性和识别可靠性（P0）

1. RTSP 看门狗、指数退避重连和状态诊断。
2. 检测置信度与匹配相似度分离。
3. 轨迹级身份状态机、滞回阈值和事件去重。
4. 多样本白名单和录入质量筛选。
5. Windows Toast、声音告警和告警冷却。
6. RTSP 凭据安全保存。
7. 手动录像、事件快照和基础自动录像。

### 第二阶段：监控和 AI 事件（P1）

1. 多摄像头 2×2/3×3 网格。
2. ROI、越线和停留检测。
3. 事件前后视频缓存和时间线回放。
4. 视频片段导出和自动清理。
5. 动物类别筛选、模型导入向导和性能统计。
6. Webhook、邮件或即时通讯通知。
7. 摄像头布局、分组和独立规则。

### 第三阶段：专业能力（P2）

1. ONVIF 自动发现和 Profile T。
2. PTZ 云台控制。
3. 动物身份识别。
4. 活体检测和反欺骗。
5. GPU/NPU 推理后端。
6. 跨摄像头目标关联。
7. 事件摘要和自然语言描述。

## 9. 推荐下一版本优先实现的五项需求

如果下一版本只能选择五项，建议按以下顺序实现：

1. 轨迹级身份状态机，解决识别结果跳变。
2. 多姿态、多样本白名单，改善上下左右脸识别。
3. 分离显示检测置信度和身份匹配度。
4. RTSP 健康监控、自动恢复和延迟显示。
5. ROI + 陌生人自动录像 + Windows 通知。

这五项可以复用当前 YuNet、SFace、YOLO 和 TrackId 管线，能够直接解决“识别跳变、RTSP 卡顿、告警不及时和没有留证”等核心问题。

## 10. 关键验收标准

### AI 识别

- 同一 TrackId 在连续短时间内不因单帧异常频繁切换身份。
- 检测置信度和身份匹配度可以分别查看和配置。
- 白名单成员至少支持多个姿态样本。
- 识别失败可以说明主要原因。

### RTSP

- 断线后可以自动重连，并在界面显示重连状态。
- 读取超时不会永久阻塞 UI。
- 可以查看最近一次连接错误和当前延迟。

### 事件和通知

- 陌生人事件可以保存快照。
- 告警在冷却时间内不会重复刷屏。
- 事件可以按时间和摄像头筛选。

### 数据安全

- 日志中没有完整 RTSP 凭据。
- 商店身份、证书和密码不出现在 Git 跟踪文件中。
- 用户可以删除本地白名单样本和识别记录。

## 11. 产品边界

- 普通人脸白名单不是高安全等级的生物认证。
- 动物检测模型判断的是类别，动物身份识别需要额外模型和样本。
- RTSP 兼容性受摄像头厂商、编码格式、网络质量和 OpenCV/FFmpeg 后端影响。
- 活体检测、门禁和高风险身份验证应使用经过认证的专业方案。
